# Impeccable 前端整体优化设计

日期：2026-06-18  
项目：多账号 Gmail 只读查看器  
设计方向：原生桌面工具 / 平衡舒适密度 / 三主题重做

## 背景

本次优化不是增加新邮件功能，而是把现有界面从“能用且已美化”推进到“长期高频使用也舒服、清楚、稳定”的桌面应用质感。用户每天面对约 30 个 Gmail 账号，界面的价值不在炫技，而在降低扫读成本、减少误点、让状态一眼可见。

## 设计目标

1. 保留现有三栏工作流，不改变用户已经形成的操作习惯。
2. 视觉上靠近 macOS 原生工具：克制、清晰、轻量、有层级。
3. 三套主题重新设计，但保持主题切换能力。
4. 信息密度采用“平衡舒适”：账号和邮件列表仍能承载高频管理，但不拥挤。
5. 清理写死颜色、零碎字号、弱对比、补丁感横幅、过度装饰和不一致弹层。
6. 所有改动不扩大产品范围，不新增发送、搜索、过滤、附件等 PRD 明确拒绝的功能。

## 视觉系统

### 主题

三套主题保留，但重新定位：

- 雾蓝：浅灰蓝背景 + 系统蓝强调色，作为默认日常主题。
- 石墨：中性灰背景 + 近黑强调色，偏专业、克制。
- 靛紫：冷白/微灰背景 + 低饱和靛紫强调色，保留产品辨识度。

主题 token 继续集中在 src/renderer/src/index.css。组件内不新增原生色阶或临时 hex；错误、警告、成功、强调色全部走语义 token 或现有 Tailwind token。

### 字体与间距

- 系统字体不变。
- 统一正文、辅助文字、元信息字号，减少 11px / 11.5px / 12px 这类零碎值。
- 邮件标题、账号邮箱、发件人、收件账号、时间各自有明确层级。
- 卡片圆角控制在 10–14px，按钮可使用小圆角或 pill，但避免过度圆润。
- 阴影只用于浮层或明确抬升，不做“边框 + 大软阴影”的装饰组合。

### 动效

- 保留现有轻量进场动画，但只用于菜单、弹层、抽屉等状态变化。
- 交互反馈以背景、文字色、轻微 active scale 为主。
- 继续支持 prefers-reduced-motion: reduce。

## 界面结构

### 顶部工具栏

工具栏保持 48px 高度和拖拽区逻辑，视觉上更像 macOS 工具栏：

- 背景使用主题 surface 半透明。
- 右侧 2FA、主题、声音按钮统一尺寸、颜色、hover、active。
- 同步状态保持轻量，不挤压图标按钮。
- Logo 与账号数保留，但字重和对比更稳。

### 左栏账号区

左栏仍是账号管理中心：

- “在用 / 归档” segmented control 保留并强化选中态。
- 账号行的选中、未读、异常、归档状态要更容易区分。
- 添加账号按钮仍是左栏唯一主 CTA。
- 分隔线使用更清楚的结构 token，避免三栏糊在一起。

### 中栏邮件列表

中栏服务快速扫读：

- 标题、发件人、摘要、时间重新排序视觉权重。
- 列表行 hover/selected/empty 状态统一。
- 顶部凭据按钮和刷新按钮保持小工具属性，不抢邮件列表焦点。
- 未选账号、暂无邮件空状态统一尺寸、图标风格和文案层级。

### 右栏邮件详情

右栏服务逐封阅读：

- 标题、发件人、邮箱、时间、收件账号形成一个完整阅读头部。
- “发给哪个账号”在 30+ 账号场景中提高可读性。
- 加载外部图片与翻译入口合并为更安静的操作行。
- 翻译未启用时不显示整宽引导横幅；只保留低占位 ghost 操作。
- 邮件 iframe 正文左缘与头部对齐。

### 弹层与抽屉

添加账号、凭据抽屉、主题选择器、TOTP 计算器统一以下规则：

- 遮罩、圆角、宽度、边框、阴影、进场动画保持同一语言。
- 错误/警告/成功提示使用语义 token。
- 主题选择器从“大展示卡片”改为更紧凑的桌面工具弹层。
- 凭据抽屉突出应用专用密码缺失这类致命状态。

## 数据流与状态

本次不改主进程、IMAP、Keychain、SQLite 数据流。所有优化限制在 renderer 视觉与交互层：

- Zustand store 的字段和行为保持不变。
- IPC channel 不新增。
- 不改变邮件同步、翻译、图片加载、TOTP 计算、凭据保存逻辑。
- 不改变账号添加流程的业务步骤。

## 错误处理

错误处理只做视觉和文案层面的清晰化：

- IMAP 登录失败、webview 加载失败、翻译失败继续沿用现有逻辑。
- 错误态使用 danger token，警告态使用 warning token，成功态使用 success token。
- 致命状态比普通空态更醒目，例如应用专用密码缺失。
- 不增加自动重试，避免违反反封控原则。

## 可访问性与响应

- 正文和辅助信息保持足够对比度。
- 图标按钮保留 title / aria-label。
- 常用图标按钮命中区不小于约 28px。
- 三栏桌面布局保持，不额外引入移动端布局。
- 键盘 focus-visible 继续使用全局焦点环。

## 验证

实现完成后至少执行：

1. pnpm typecheck
2. pnpm build

视觉验收重点：

- 三套主题切换后没有突兀硬编码颜色。
- 三栏结构线清楚但不吵。
- 30+ 账号时左栏仍紧凑可扫。
- 邮件详情头部和正文对齐。
- 添加账号、凭据抽屉、主题选择器、TOTP 弹层风格一致。
- 空状态、错误态、成功态不再像临时补丁。

## 非目标

本次不做：

- 发送邮件
- 跨账号搜索
- 邮件过滤
- 附件预览
- 已读/未读修改
- Gmail API / OAuth
- webview 登录伪装
- 主进程重构
- 数据库结构变更

## 实施边界

优先修改 renderer 层文件：

- src/renderer/src/index.css
- src/renderer/src/components/layout/*
- src/renderer/src/components/accounts/*
- src/renderer/src/components/messages/*
- src/renderer/src/components/detail/*
- 必要时少量调整 common 组件

不碰主进程和存储层，除非 typecheck 暴露与已有未提交改动相关的类型问题。
